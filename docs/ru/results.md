# Результаты

Железо: 2× MI50 16 ГБ (с турбинами), Xeon E5-2666 v3, X99, Ubuntu 24.04, ядро 6.8, лимит 85 Вт
на карту, уровень DPM `high`, крупный BAR и P2P включены ([hardware.md](hardware.md)). Модель:
`unsloth/Qwen3.8-27B-GGUF`, `Qwen3.8-27B-Q4_0.gguf` (16.1 ГБ) + `MTP/mtp-Qwen3.8-27B-Q4_0.gguf` (1.4 ГБ).

**Главная метрика:** скорость генерации на записанном настоящем запросе агента (Claude Code, промпт
17K токенов, 22 инструмента, размышление включено), 6000 токенов ответа, замер на стороне клиента.
Короткие синтетические тесты прячут и скорость спекуляции, и зависания.

## По шагам

| Конфигурация | Генерация, ток/с | Промпт, ток/с | Устойчивость |
|---|---|---|---|
| llama.cpp b10621, ROCm 6.3, `-sm layer`, без MTP | 19.4 | 330 | чисто |
| b11235, `layer`, MTP | 25–26.5 | 280 | одно полное зависание машины за ~5 прогонов |
| b11235, `-sm tensor`, без MTP | 29.3 | 345 | зависание ~1 из 4 |
| b11235, `tensor` + MTP черновик 3, ROCm 6.3 | 39–45 | 325 | зависание ~1 из 8–14 |
| b11235, `tensor` + MTP, **ROCm 7.14** | 40.0 (клиент), ~44 (журнал сервера) | 338 | **0 из 30**, нагрузка 6 × 900 с чисто |
| **+ 3 заплаты этого репозитория** | **48.3** (клиент) | 338 | 6 × 900 с + 6 запросов агента чисто |

Тот же текст, жадный выбор (temperature 0): 43.1 → 48.7 ток/с с заплатами.
Первый токен при промпте 17K — ~51 с (промпт ~338 ток/с). Внутри одного разговора читаются только
новые токены хода: 40–140, меньше секунды.

`llama-bench` (без MTP, ток/с, контекст 0 / 16K): `layer` 22.0 / 19.8; `tensor` 31.3 / 29.5.

Один проход на 2 картах (`llama-bench -p 1,4`): 1 токен 31.3 мс; 4 токена 51.0 мс без заплат,
43.2 мс с заплатами (это проход проверки MTP).

Длина черновика MTP (детерминированный запрос агента): 2 → 42.6, **3 → 46.1**, 4 → 42.5, 5 → 40.5 ток/с.

## Качество

- **Вывод побитово тот же**: жадный ответ на запрос агента с тем же md5, что у b11235 без заплат.
- Перплексия / KL-дивергенция против эталонной сборки, 10 × 2048 токенов русского технического
  текста, пакеты по 4 токена (`-b 4 -ub 4`, чтобы работал пропатченный кернел):
  PPL 5.1500 против 5.1528 (без заплат), KLD 0.00547 против 0.00534 (±0.00015), тот же первый
  токен 96.7 %. Для масштаба: Q4_0 против Q8_0 обычно даёт KLD 0.02–0.05.
- Сборка на ROCm 7.14 против 6.3: PPL/KLD те же.

## Пробовали — не помогло

| Что | Итог |
|---|---|
| vLLM, форк gfx906 (`aiinfos/vllm-gfx906-mobydick`), GPTQ-Int4, TP=2, MTP 3 | 34.7 ток/с, первый токен 71 с против 51, KV-кэш только на 64K, старт 11 мин. «Промпт 1720 ток/с» в его журнале — артефакт усреднения за 10 с. Кэш префикса для гибрида работает (`--mamba-cache-mode align`), но генерацию он не ускоряет |
| vLLM + MTP 2 + кэш префикса | 33.7 ток/с |
| AWQ вместо GPTQ в vLLM | не пробовали: в этом форке AWQ идёт тем же GEMM-путём gfx906 |
| Лимит 90 / 95 / 100 Вт вместо 85 | +1 % / +5 % / — ; турбины с тихих уходят на 62–66 %. Шума не стоит |
| `--spec-draft-backend-sampling`, `-bs` (выбор токена на карте) | без изменений |
| `HSA_ENABLE_SDMA=0` | без изменений |
| Черновая голова MTP на одной карте (`-devd ROCm1`) | без изменений |
| `--spec-draft-n-max 4` | принимается больше, но проверка 5 токенов дороже; выигрыша нет |
| n-граммная спекуляция (`ngram-mod`, `ngram-map-k`) | на задачах «написать с нуля» ничего |
| Слияние gate+up на 2–4 столбцах | медленнее: 56.6 против 43.2 мс на проход 4 токенов (регистры уходят в память) |
| GEMV Q4_0 через LDS | один столбец уже ~595 ГБ/с из ~700; LDS-варианты медленнее |
| Синхронный `set_tensor` для мелких входов | без изменений |

## Куда уходит время сейчас

Один шаг MTP (~61 мс, принимается ~3 токена): проход проверки ~44 мс работы карт, черновые
проходы по ~3 мс и **10–17 мс простоя карт на границах проходов** (копия логитов на хост, выбор
токена на CPU по словарю 248K, запись входов графа на каждую карту). Это следующая цель —
[how-it-works.md](how-it-works.md).
