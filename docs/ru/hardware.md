# Железо и BIOS

## 1. Крупный BAR: `Above 4G Decoding`

Включите `Above 4G Decoding` (обычно `Advanced → PCI Subsystem Settings`) и Resizable BAR, если плата
его предлагает. `CSM` отключать не нужно.

Ловушка: `mem_info_vram_total` показывает 16 ГБ **даже при BAR в 256 МБ** — драйвер читает это число
из карты, мимо окна BAR. Проверять надо *видимую* память:

```bash
cat /sys/bus/pci/devices/0000:XX:00.0/mem_info_vis_vram_total   # нужно 17163091968 (16 ГиБ), не 268435456
```

`scripts/check-system.sh` делает это для каждой карты. С BAR в 256 МБ всё работает, но на 2× MI50
включение крупного BAR дало **+18 % генерации**, и без него не будет P2P (ниже).

## 2. P2P между картами: окно MMIO выше 4G должно лежать ниже 16 ТиБ

На платах Xeon E5 / X99 обычно есть ещё два пункта: `MMIOH Base` и `MMIO High Size` (названия
плавают: `MMIO High Base`, `PCI 64-bit Resource Allocation`, разделы Chipset / North Bridge).

| Пункт | Значение |
|---|---|
| `MMIOH Base` | **`4T`** (любое ниже `16T`; не сам `16T` и не `56T`) |
| `MMIO High Size` | `256G` |

Адресация DMA у Vega 20 — **44 бита (16 ТиБ)**. При апертуре на 56 ТиБ ядро отказывает в P2P между
картами (`amdgpu_device_is_peer_accessible`), `p2p_links` пусты, и `-sm tensor` откатывается на
медленные копии: 38.5 ток/с против 79 на том же тесте после переноса базы на `4T`.

```bash
ls /sys/class/kfd/kfd/topology/nodes/*/p2p_links         # у узлов-карт должно быть непусто
sudo dmesg | grep "amdgpu.*BAR 0.*assigned"             # адреса ниже 0x100000000000
```

Прямого моста между слотами на большинстве плат X99 нет; P2P идёт через корневой комплекс
процессора, и этого хватает.

**Настройки BIOS могут слетать сами** (садится батарейка CMOS). Потеря `Above 4G` роняет видимую
память до 256 МБ и стоит ~18 % скорости. Если проверка выше однажды «переключилась» — меняйте CR2032.

## 3. Платформа

- **Xeon E5 v3/v4 (LGA2011-3) или новее.** У Sandy/Ivy Bridge (E5 v1/v2, LGA2011) нет PCIe-атомиков:
  `amdkfd` пишет `PCI rejects atomics` и карту не инициализирует.
- Проверено на PCIe 3.0 x16 на карту; трафик all-reduce при `-sm tensor` небольшой.
- **Драйвер amdgpu — встроенный в ядро.** Не ставьте `amdgpu-dkms` / `amdgpu-install`; ROCm живёт
  внутри контейнера.

## 4. Питание, тепло, шум

MI50 пассивная; в обычном корпусе ей нужна турбина (проверено: турбина Delta BFB0712HF в кожухе на
каждой карте). Заводской лимит 250 Вт такое охлаждение не держит (~100 °C junction). Измерено здесь:

| Лимит на карту | Генерация | Junction (горячая карта) | Турбины |
|---|---|---|---|
| 85 Вт (используется) | 48.3 ток/с | ~80–83 °C | ~45–55 % |
| 90 Вт | ~48.8 (+1 %) | ~83 °C | в среднем 59 %, >60 % 12 % времени |
| 95 Вт | ~50.6 (+5 %) | ~83–85 °C | 62 % постоянно |
| 100 Вт | — | 85–86 °C | 62–66 % за 2 мин |

Как задать лимит (root, для каждой MI50; значение в микроваттах, сбрасывается при перезагрузке;
PCI-адрес каждой карты печатает `scripts/check-system.sh`):

```bash
echo 85000000 | sudo tee /sys/bus/pci/devices/0000:XX:00.0/hwmon/hwmon*/power1_cap
```

Уровень DPM `high` (`echo high | sudo tee /sys/class/drm/cardN/device/power_dpm_force_performance_level`)
снимает парковку частот между кернелами; на этой же машине на другой модели измерено +12.7 % генерации.

Даунвольт (кривая OverDrive) на MI50 работает, но запас у каждой карты свой: здесь −50 мВ было
безопасно, а −75 мВ **молча портило результаты** без всякого падения. Только с проверкой вывода.
